# Portfolio QA Checklist

Use after UI implementation.

---

# Content integrity

- [ ] No invented project metric
- [ ] No invented user count
- [ ] No inflated ownership
- [ ] WEARUP reflects the recorded backend, access-control, and deployment contribution without claiming the full rental/inventory domain
- [ ] DreamLens AI improvement is qualitative; no invented evaluation metric or claim of model training
- [ ] ISMS-P is explicitly labeled mock
- [ ] Professor-as-virtual-representative context is preserved
- [ ] Proofolio is visibly AI-assisted
- [ ] 먹어도 돼? is not presented as a production medical system
- [ ] ActorLab is not presented as a completed primary project

---

# Desktop

Validate around:
1440px

Check:

- [ ] Header alignment
- [ ] Hero hierarchy
- [ ] No text clipping
- [ ] No horizontal overflow
- [ ] Featured project visual has correct aspect ratio
- [ ] Project layout is not visually repetitive
- [ ] Long Korean text has readable line length
- [ ] Section spacing feels deliberate
- [ ] Links visibly respond to hover/focus

---

# Mobile

Validate:
390px

Check:

- [ ] No horizontal scrolling
- [ ] Header/menu works
- [ ] Hero headline wraps intentionally
- [ ] Project image does not overflow
- [ ] Metadata does not become unreadably dense
- [ ] Buttons/links have adequate touch target
- [ ] Project sections recompose rather than shrink
- [ ] Technology list wraps cleanly
- [ ] Long Korean text does not create awkward overflow

---

# Accessibility

- [ ] One meaningful H1
- [ ] Logical heading sequence
- [ ] Buttons are buttons
- [ ] Links are links
- [ ] Inputs have labels if present
- [ ] Images have appropriate alt text
- [ ] Decorative imagery has empty alt
- [ ] Keyboard focus is visible
- [ ] Navigation is keyboard accessible
- [ ] Text/background contrast is reasonable
- [ ] Reduced-motion preference is respected

---

# Interaction

- [ ] Hover effects do not cause layout shift
- [ ] Navigation state is clear
- [ ] Motion is subtle
- [ ] No interaction depends exclusively on hover
- [ ] External links behave consistently
- [ ] Resume/GitHub links work

---

# Quality

- [ ] No console errors introduced
- [ ] No broken assets
- [ ] No unused temporary components
- [ ] No unnecessary dependency
- [ ] No duplicate styles without reason
- [ ] No placeholder lorem ipsum remains
- [ ] No AI-generated fake data remains

---

# Final visual review

Ask:

1. Does the first screen explain the candidate?
2. Is DreamLens clearly the primary project?
3. Can the candidate's actual role be understood quickly?
4. Does the site avoid looking like a generic SaaS template?
5. Are project boundaries visible?
6. Does the site communicate build → verify → secure?
7. Would a recruiter understand the strongest evidence in under a minute?
